AI 101 — 做出來、上線、記下來——然後是你的儀器

目標。休息之前，你已經用 AI 程式代理（coding agent），從一份你自己寫的五行規格做出一個倒立擺模擬器、用物理檢驗過它、把它放上公開的網路掛著你的名字，並寫下第一則 Markdown 工作紀錄。 兩小時結束時，你自己的手機 App 已經在和你手上的 ESP32 對話——一個按鈕作用在開發板上、一個即時數字回傳——由你燒錄、在你的手機上驗證、以 pull request 交付。你也知道班級板上哪一個區塊（block）是你的。

學習目標：從你自己寫的規格出發與 AI 程式代理合作 · 用物理檢驗 AI 的產出，而不是看起來像就好 · 把程式放上公開網路並在手機上打開 · 保持一份下一個 session 能接續的 Markdown 紀錄 · 做出一個和你的 ESP32 對話的手機 App、燒錄、以 PR 交付 · 知道你的區塊。

為什麼從專題以外的東西開始。AI 輔助工作是一種通用技能。同樣的三個動作可以用在模擬、網站、影片、報告、KiCad 電路板與韌體驅動程式上： 從一份寫下來的規格做出來（build）、上線到別人看得到的地方（ship）、用純文字記下來你做了什麼（log）。 今天把這三個動作練兩次：先在每位物理人都懂的東西——單擺——上，沒有硬體礙事；再用在你手上的 ESP32 上，做一個你自己的手機 App。電子設計只是 AI 的一種應用，不是課綱本身。

一句話核心論點：AI 代理就像一位沒有記憶的菜鳥工程師——它的表現，完全取決於你給它的專案文件、 任務規格與驗證方式。以下所有內容都由這句話推導而來。

先修條件：課前準備檢查清單（workbook 第 0 章，最多一小時，不計入 10 小時的作業時數）——包括一個已連上 GitHub 的免費 Cloudflare 帳號。 請帶筆電與 USB 線；開發板（ESP32-S3）一開始就發給你，已預先燒錄骨架韌體——15:35 你要燒錄自己的版本，所以 PlatformIO 的工具鏈必須在家先下載好。

我們的工作方式：自己的東西放自己的儲存庫，儀器放一個班級儲存庫，每個螢幕上都有家教

做出來（Build）

先寫規格——五行，你自己寫。然後是計畫，然後才是程式碼。今天：一個倒立擺，寫在單一個 index.html 裡（canvas＋JavaScript，不用框架、不用建置）。 代理寫樣板程式碼；參數由你設定，檢驗由你來做。

上線（Ship）

你自己的 GitHub 儲存庫 pendulum，直接從 git 部署到 Cloudflare Pages—— 不需要建置指令，一個公開的 *.pages.dev 網址，每次 push 自動重新部署。備案是 GitHub Pages。這個儲存庫會成為你個人的課程頁面。

記下來（Log）——用 Markdown

每次 session 結束都寫 PROGRESS.md：已完成／已驗證／下一步／注意事項。純文字，放在程式碼旁邊：可以 diff、可以搜尋、 AI 在下一個 session 開始時會讀它，而且它就是你這門課的實驗記錄本。規格、紀錄、筆記、README、投影片——Markdown 是 AI 工作的共通語言。

Claude 家教（tutor）

在 Claude Code 中輸入 /tutor L1，它會用英文或中文陪你走完今天的 workbook 章節：檢查你的工具鏈、掌控每一步的節奏、 在你的 SPEC.md 存在之前拒絕寫程式碼、在你 commit 之前先問「你量到什麼？」，並和你一起寫 PROGRESS.md。之後還有 /tutor HW1、/tutor L2……

儀器——同樣的動作，用在硬體上

一個班級儲存庫 TIGP-Experimental-Methods/class-board-2026：firmware/（PlatformIO）、host/（手機 App＋instrument.py）、 hardware/（KiCad）、workbook/、tutor/，以及你的資料夾 docs/students/<name>/。ESP32-S3 上的韌體 ↔ WebSocket ↔ 手機網頁 App ↔ Python。開發板本身就是一個 WiFi 存取點。 main 受保護；你在分支與 pull request 上工作；由授課教師合併。

你的區塊

班級板有五個學生區塊——B1 輸入 · B2 電源 · B3 輸出 · B4 切換 · B5 數位／TRIG——以及五位學生。今天結束時 每個人都擁有一個：你會讀懂它、佈線它、寫它的驅動程式，並在成果展上展示它。

五大工作方法（本課程的主軸）

  1. 規格先行。需求寫在檔案裡（SPEC.md），而不是留在聊天紀錄中；先要求計畫，再要求程式碼。今天的規格只有五行，由你自己寫。
  2. 教會儲存庫，而不是教會 session：CLAUDE.md。慣例、腳位定義、建置／燒錄指令、如何測試——寫一次，每個 session 都會載入。
  3. 小而新的 session。一個任務＝一個 session；做完、commit、重新開始。太長的 session 會腐壞。
  4. 交接紀錄——用 Markdown。每次 session 結束都要更新 PROGRESS.md：已完成／已驗證／下一步／注意事項。把實驗記錄本的紀律套用到 AI 工作上。
  5. AI 動手寫，你來驗證。沒有驗證計畫 → 產出就不是你能交付的東西。在本課程中，「驗證」指的是一個數字或一個觀察：擺動週期符合 2π√(L/g) 嗎？你在手機上／在 DRC 裡／在示波器上看到什麼？

班級儲存庫本身也是這樣建起來的：課程文件、workbook 與家教 skill，就是這門課自己的 CLAUDE.md 與交接日誌。

時間時段內容

0:57休息（5 分鐘）
1:02儀器在你的手機上（10 分鐘）你那塊預先燒錄的開發板是一個存取點 instrument-<id>：加入它、開啟 http://192.168.4.1、按下 LED 按鈕、看即時圖表動起來——每個人，現在。 軟體架構投影片（韌體 ↔ WebSocket ↔ PWA ↔ instrument.py），以及一個控制項會碰到的兩個檔案：firmware/src/blocks/base/ 裡的處理函式與 host/pwa/ 裡的控制元件，還有那一則穿過 WebSocket 的訊息。
1:12練習 E2：你的手機 App 和你的 ESP32 對話（33 分鐘）一個按鈕出去、一個即時數字回來。挑一個按鈕動作（LED 顏色、閃爍模式、一支 GPIO 高／低、閒置腳位上的蜂鳴）和一個讀值 （晶片溫度 temperatureRead()、觸控腳位、按鈕次數計數器、ADC 腳位）。和家教一起：在 blocks/base/ 加入處理函式與狀態欄位、在 App 的你的面板加入控制元件與數字； pio run -t upload；手機重新連上；按下按鈕、看數字。git switch -c e2-<name>、commit、push、開 PR 並附手機截圖。家教依範例寫樣板程式碼，但訊息名稱、處理函式內容與控制元件標籤由你親手改。 你的 App 在你的手機上驅動你的開發板並顯示來自它的即時數字即完成——沒做到的人不下課。
1:45班級板（10 分鐘）電路圖 PDF 第 1 頁（方塊圖）；每個區塊一句話（B1 輸入 · B2 電源 · B3 輸出 · B4 切換 · B5 數位／TRIG）；3 × 4 SMA 前面板圖； 區塊分配——先自願，再抽籤。家教把你的區塊記進 PROGRESS.md。五個名字對上五個區塊即完成。
1:55作業說明（5 分鐘）作業 1 的五個勾選框；LINE 群組；週三 16:00 的辦公時間。家教替你排好檢查點（週二／週四），並以你的 PROGRESS.md 更新結束這個 session。

作業 1（列入評分，2.5 小時）— 練習 E2（完成）＋E3–E5

  • E2 完成＋合併（0.5 小時）。如果你的 App 在課堂上沒有完全做好，用 /tutor HW1 完成它（燒錄有問題就到週三辦公時間）。授課教師週一審查 PR；回應一則意見並合併。學到：PR 循環。
  • E3（0.5 小時）讀懂你的區塊。家教展示你區塊的 PDF 頁面並問兩個問題（B1「為什麼每個輸入都串了一個 1 kΩ？」· B2「USB 和電源插座同時插上會發生什麼？」· B3「±10 V 的擺幅是由什麼決定的？」· B4「跨在繼電器線圈上的二極體是做什麼的？」· B5「為什麼 GPIO 不能直接驅動 5 V TTL？」）。 答案寫進 docs/students/<name>/notes.md。觀看 V3。學到：電路圖閱讀、你的區塊的用途。
  • E4（0.5 小時）KiCad 就位。安裝 KiCad 10；把零件庫套件解壓到儲存庫裡；開啟 class-board.kicad_pro；找到你的規則區域（rule area）；截圖。觀看 V4。學到：認識 KiCad。
  • E5（0.5 小時）你的 SPEC 段落。在 docs/students/<name>/SPEC.md 寫一段：你的區塊必須做到什麼、一個數字、成果展當天你要怎麼展示它——就是倒立擺的規格，再往上一層。學到：規格先行。
  • 影片 V3＋V4（16 分鐘）與 workbook 第 1 章的閱讀填滿其餘的 2.5 小時。每次工作 session 結束都要寫一筆 PROGRESS.md 並 commit——在你的 pendulum 儲存庫和班級儲存庫都一樣。這條規則貫穿整個課程。

本週結束時的評分依據：你的倒立擺網址與它的 PROGRESS.md（課堂上完成）、已合併的 E2（你的 App）、notes.md 裡的兩個答案、區域截圖與 SPEC.md——全部在儲存庫裡，全部透過 commit 或 PR。

這三個動作接下來去哪裡

  • 做出來：你在電路板上的那一部分（第二講）、你區塊的驅動程式與 App 面板（第三講《韌體與機械 101》）——E2 的 App 長成真正的區塊面板；同樣是規格 → 計畫 → 樣板 → 你改最關鍵的幾行 → 驗證。
  • 上線：9 月 28 日班級板從大家的 pull request 下單；你的面板隨儀器的 App 出貨；你的倒立擺網站早已公開。
  • 記下來：每次 session 結束寫 PROGRESS.md；總結週時 SPEC.md 多一個量到的數字。
  • 你的個人頁面：pendulum 儲存庫就是你的課程頁面。總結週時你把 60 秒影片與量到的數字加進去；成果展把它連結在你的區塊旁邊。同一個網站，每週多一點——這就是「show your work」。
  • 用 AI 做影片、投影片、報告（可選，第三講起）：本實驗室的 show-your-work Claude Code skills—— education-video、slide-deck、technical-report、natural-voice、showoff-render——用 python tools/install_skills.py <repo> 一行裝進任何儲存庫。想用它們做 60 秒影片或成果展投影片都可以；手機拍的影片同樣合格。
